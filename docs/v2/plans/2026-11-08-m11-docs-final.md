## Global Constraints
- No e-mail addresses, session links or model names in repo files; no AI attribution anywhere.
- Docs state what is built, not what is hoped: anything not device-verified is marked "not run on a device".
- PBD1 stays through 0.3.0 (owner ruling 2026-11-08); the docs say so and name the release in which it may go.
- Version bump 0.3.0 touches `Cargo.toml` workspace version and the Android `versionName`/`versionCode`; `min_compatible` does not change.
- One commit per task starting with the task ID; ticks PROGRESS; push after every task. The final push goes to `cloud/v2-upgrade` only, no pull request.

## Review Focus
1. **Docs claim a feature that is not built or not device-checked:** `check-docs.sh` and the reviewer compare every "implemented" claim with PROGRESS and DEVICE-CHECKS. Test: `docs_claim_only_ticked_features` (M11.1).
2. **A capability or wire field missing from WIRE_PROTOCOL:** `every_local_capability_is_documented` (M11.2).
3. **The checklist cannot be followed by an agent without the owner:** each check names setup, exact commands or taps, expected result, and a "needs the owner" tag. Test: `every_check_has_expected_result` (M11.5).
4. **A stale "draft", "planned" or "reserved" word after the feature shipped:** `no_stale_status_words` (M11.2).
5. **Final review misses an area:** reviewers are split by area per the global rules (M11.6).
