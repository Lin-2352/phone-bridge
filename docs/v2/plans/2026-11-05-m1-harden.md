# M1 Harden (Top 12) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Budget mode for this program: superpowers:executing-plans, inline.

**Goal:** close the 12 priority findings of `docs/REVIEW-2026-11-04.md` and add fuzzing for the existing parsers.

**Architecture:** every fix puts its rule in a small pure function (Rust or Kotlin) with JVM or cargo tests, and the platform code only calls it. Windows-only behaviour gets `#[cfg(windows)]` tests that run in CI's windows job. Device-only behaviour goes into the checklist (M11.5).

**Tech Stack:** Rust 1.99.1 (pb-tray, pb-transport, pb-ffi), Kotlin and Compose (Android app), Gradle, cargo-fuzz on a pinned nightly.

**Spec:** [docs/v2/SPEC.md](../SPEC.md), milestone M1. Findings: [docs/REVIEW-2026-11-04.md](../../REVIEW-2026-11-04.md). Progress: [docs/v2/PROGRESS.md](../PROGRESS.md).

## Global Constraints
- **Security model:** "the PC can only ask". Nothing here may let the PC decide for the phone.
- **Wire changes:** each new message or field is optional and backward compatible (protocol version stays 0). An old peer that ignores it still works.
- **Defaults:**
  - Auto-copy of shared text: **off**.
  - Shortcut files (`.lnk .url .scf .library-ms .searchConnector-ms`): **refused** unless allowed.
  - Risky types always prompt.
- **No text in toasts:** a toast or balloon about shared text never contains the text.
- **Tests:** a new decision always gets a JVM or cargo test that is seen failing first.
  - Run Android tests here with `ANDROID_HOME=~/android-sdk bash gradlew :app:testDebugUnitTest` (setup in PROGRESS.md).
  - Run Rust tests with `cargo test --workspace`.
- **Commits:** the subject starts with the task ID (`M1.x`). The same commit ticks PROGRESS.md. Push after each task.

## Review Focus
1. **System-UI Stop:** the user taps Android's own "Stop sharing" chip while the phone is unlocked. That must still count as a user stop (M1.2: the reason depends on lock state, not just on the callback).
2. **Prompt stuck on:** a consent prompt that never reports back (killed activity) must not pause remote input forever (M1.5: the guard expires after 120 s).
3. **Disguised file names:** names like `photo.jpg.exe`, `INVOICE.PDF.LNK`, `a.exe.` (trailing dot), `a.exe ` (trailing space). Risk detection must use what Windows will execute (M1.7 tests).
4. **No streams:** a FAT or exFAT save folder rejects the Zone.Identifier stream. The save must still succeed and only log (M1.7).
5. **Fresh checkout:** a checkout without the release key must still configure and build `debug` and `qa`. Only `assembleRelease` fails (M1.12).

  - `portable.rs` applies that SDDL to `data\` at every start.

- Tests:
  - `everyone_write_is_unsafe`
  - `authenticated_users_modify_is_unsafe`
  - `owner_system_admins_only_is_safe`
  - `deny_aces_do_not_make_it_unsafe`
  - `data_dir_sddl_has_no_inheritance_and_three_principals`

**8b. Camera install refuses unsafe folders and uses an embedded DLL**
- `build.rs` in pb-tray: when `PB_CAMERA_DLL` is set, copy the DLL to `OUT_DIR` and emit `cargo:rustc-cfg=embedded_camera_dll`.
- `register_elevated`:
  - uses the embedded bytes;
  - otherwise reads the file beside the exe, but only from a safe folder (`EXIT_UNSAFE_FOLDER`).
  - `request_register` checks the folder first.
- Shipping:
  - `make-portable.ps1` and CI build `pb-camera-source` first, then set `PB_CAMERA_DLL`.
  - The zip no longer ships `pb_camera_source.dll` beside the exe.
- Test: `embedded_dll_is_used_when_present`. The source choice is a pure function: `fn dll_source(embedded: bool, folder_safe: bool) -> Option<DllSource>`.

**8c. DLL planting**
- `SetDefaultDllDirectories(LOAD_LIBRARY_SEARCH_SYSTEM32)` runs as the first statement of `main` (Windows).
- Imports that aren't KnownDLLs are delay-loaded: `build.rs` emits `/DELAYLOAD:<dll>` for them and links `delayimp.lib`. `/DEPENDENTLOADFLAG:0x800` is added as well.
- CI planting test in `windows-zip`:
  1. Copy `Relay.exe` into a temp folder.
  2. For every imported DLL, write a garbage file under its name.
  3. Run `Relay.exe --version` (add the flag if it's missing). It must exit 0.
