# M0 Baseline Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Budget mode for this program: superpowers:executing-plans, inline.

**Goal:** a toolchain and CI baseline for the v2 program. Nothing in the apps changes except a 32-bit size fix.

**Architecture:**
- CI workflow changes, plus a bash build script that twins `android-build.ps1`.
- Small Gradle and `deny.toml` additions for `armeabi-v7a`.
- One Rust helper, so a u64 size is never truncated on 32-bit.

**Tech Stack:** GitHub Actions, bash, Gradle (AGP 9.4.1), cargo-ndk, Rust 1.99.1.

**Spec:** [docs/v2/SPEC.md](../SPEC.md), milestone M0. Progress: [docs/v2/PROGRESS.md](../PROGRESS.md).

## Global Constraints
- **Toolchain:** Rust `1.99.1`, the CI pin.
- **Android:**
  - `minSdk 29`, `targetSdk 36`, `compileSdk 36`, unchanged.
  - ABIs: `arm64-v8a`, `armeabi-v7a`, `x86_64`.
  - Native libraries keep `-C link-arg=-Wl,-z,max-page-size=16384` (16 KB pages).
- **Actions:** every `uses:` pins a 40-hex commit SHA, with the tag in a trailing comment.
- **No behaviour change** in either app, apart from Task 4.
- **Commits:**
  - The subject starts with the progress ID (`M0.x`).
  - The same commit ticks `docs/v2/PROGRESS.md` and moves "Resume here".
  - Push after every task.

## Review Focus
1. **Annotated tags:** an annotated tag's object SHA is not a commit, and Actions rejects it as a pin. Task 3 pins the peeled `^{}` commit.
2. **Missing native libraries:** unit tests and lint must run on a checkout without `jniLibs`. Task 6 runs them before any native build.
3. **Stray `.so` files:** cargo-ndk copies iroh's stub `.so` files into `jniLibs`. Task 5 deletes everything except `libpb_ffi.so`, as the PowerShell script does.
4. **Page-size flag:** the 16 KB flag must reach all three ABIs, and must not reach the host build used for bindings. Task 5.
5. **32-bit sizes:** a remaining size of 4 GiB or more on 32-bit Android. Task 4 tests it.

### Task 4 (M0.9): no 32-bit truncation of transfer sizes
**Files:** modify `crates/pb-transport/src/files.rs`: line 462, plus a helper next to `CHUNK` (line 28) and a test in its `tests` module.

**Interfaces:** produces `fn chunk_len(remaining: u64, chunk: usize) -> usize`, the smaller of the two. It never truncates, whatever the width of `usize`.

- [ ] Write the failing test:
```rust
#[test]
fn chunk_len_never_truncates_large_remainders() {
    assert_eq!(chunk_len(1 << 32, CHUNK), CHUNK);
    assert_eq!(chunk_len((1 << 32) + 5, CHUNK), CHUNK);
    assert_eq!(chunk_len(5, CHUNK), 5);
    assert_eq!(chunk_len(0, CHUNK), 0);
}
```
- [ ] Run `cargo test -p pb-transport chunk_len`. Expected: compile error, because `chunk_len` is not defined.
- [ ] Implement it as `usize::try_from(remaining.min(chunk as u64)).unwrap_or(chunk)`. Line 462 becomes `let want = chunk_len(size - done, CHUNK);`.
- [ ] Run `cargo test -p pb-transport`. Expected: it passes. Then run clippy (`-D warnings`).
- [ ] Commit `M0.9: never truncate the remaining size on 32-bit (armeabi-v7a)`, then push.
