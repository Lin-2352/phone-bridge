# Relay UI v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give Relay a professional UI on both platforms: a Direct2D main window next to the tray on Windows, a four-tab Compose app plus a widget on Android, one shared design system, and a privacy-safe Timeline.

**Architecture:**
- **Design tokens:** `design/tokens.toml` generates checked-in Rust and Kotlin token files.
- **PC drawing:** the tray's drawing kit (`fluent.rs`) moves from GDI to a Direct2D `Canvas` (`d2d.rs`). It uses a DirectComposition swap chain where Mica shows and an HWND swap chain elsewhere. A new `main_window.rs` hosts Home / Timeline / Devices / Settings and replaces `settings_window.rs`.
- **Android:** `MainActivity` becomes a NavHost with four tabs. `Timeline.kt` replaces the in-memory `Bridge.recent`.

**Tech Stack:**
- PC: Rust 2021 and `windows` 0.62 (features Direct2D, DirectWrite, DirectComposition, DXGI; no new crates in `pb-tray`).
- Tokens generator: `toml` 0.8, used only in `tools/gen-tokens`.
- Android: Kotlin / Jetpack Compose (BOM 2025.06.01), `navigation-compose`, `material-icons-extended`, Glance `glance-appwidget`, `androidx.core` AtomicFile.

**Spec:** `docs/superpowers/specs/2026-10-29-ui-v2-design.md` (read it with this plan).

## Global Constraints

- User-visible text says "Relay". Internal identifiers keep their names: `pb-*` crates, `dev.phonebridge.app`, `%LOCALAPPDATA%\PhoneBridge\tray`, `\\.\pipe\PhoneBridgeTray-<user>`, window classes, the toast identity.
- Timeline stores metadata only. It never holds clipboard text, image bytes, file bytes, notification titles or notification bodies. Caps: 1,000 entries and 30 days.
- Mica windows (main window, flyout) use `CreateSwapChainForComposition` + `DXGI_ALPHA_MODE_PREMULTIPLIED` + `CreateTargetForHwnd(hwnd, FALSE)`. All other windows, and every window when Mica is unavailable, use `CreateSwapChainForHwnd` with opaque surfaces.
- Budgets with the main window open: working set under 40 MB, first paint under 200 ms, idle CPU near 0 (the frame timer runs only while animating).
- Motion: fast 120 ms, normal 200 ms, emphasised 300 ms. Spacing 4/8/12/16/24/32. Radii 4/8/12/20. Type: caption 12, body 14, subtitle 16, title 20, display 28.
- Brand colours: primary cobalt `#3651C5`, accent amber (the value already in `Theme.kt`).
- Process rules:
  - Never add AI attribution to commits; commit as the local git user.
  - Write a failing test first for every behaviour.
  - Run one cargo command and one gradle command at a time.
  - Stop `pb-tray.exe` before rebuilding it.
  - Install only a freshly built APK.
  - Phone rules: no `KEYCODE_SLEEP`, no `settings put`, always `adb -s 79KRFEJVPVOBQCHQ`, and the user taps every consent or permission prompt.
  - PC screenshots are window-only (PrintWindow); never capture the full screen.
- Env (Git Bash): `export RUSTUP_HOME=D:/Rust/rustup CARGO_HOME=D:/Rust/cargo PATH="/d/Rust/cargo/bin:$PATH" ANDROID_HOME="$LOCALAPPDATA/Android/Sdk" JAVA_HOME="C:/Program Files/Java/jdk-21"`.
- Gates before each commit that touches code:
  - Rust: `cargo fmt --check`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test -p <crate>`.
  - Android: `./gradlew :app:testDebugUnitTest` (in `android/`).
  - At the end of the branch: `cargo test --workspace`, `cargo deny check` and `./gradlew lintRelease`.

## Rulings made while planning

- **`fluent.rs` signatures.** The spec says "same signatures", but the GDI handle cannot survive. So the functions keep their names and argument order; `hdc: HDC` becomes `c: &mut Canvas`, and `Fonts`/`HGDIOBJ` becomes a `Font` enum. Callers change mechanically.
- **D3D device.** `screen_render::device_for_window` sets `VIDEO_SUPPORT`, which can fail on WARP (CI). So adapter selection is extracted into `screen_render::adapter_for_window(hwnd) -> Option<IDXGIAdapter>`. `d2d.rs` creates its own device with `BGRA_SUPPORT` only, falling back to `D3D_DRIVER_TYPE_WARP`.
- **Settings search.** It currently reads `WM_CHAR` into a custom field. It moves to the new `SearchBox` (`EDIT`) when Settings moves into the main window (Task 11). Search behaviour (`settings_window::items(m, page, query)`) stays as it is.
- **Phone-side "PC no longer recognises this phone".** This needs `PbNode::peer_changed(peer_id: String) -> bool` exported from `pb-ffi` (it wraps `Node::peer_changed`). The bindings are then regenerated with the repo script (Task 18).

## Review Focus

1. **Moving the main window to a monitor with different scaling (`WM_DPICHANGED`).** Text formats, the swap chain and the layout rebuild at the new DPI, with no blur and no clipped text. Test in Task 8.
2. **Windows switching light/dark while windows are open (`WM_SETTINGCHANGE` "ImmersiveColorSet").** All open windows repaint in the new palette without a restart. Test in Task 3.
3. **Very long, emoji or right-to-left file names in Timeline and Home rows.** They are ellipsized inside the row and never overlap the time or the buttons. Test in Task 4.
4. **Timeline with the full 1,000 entries.** Scrolling lays out only visible rows and stays smooth. Test in Task 4 (`visible_range`) and Task 10.
5. **Relay exiting within the 1 s debounce after a transfer.** The last entry is still on disk next start. Test in Task 7.
