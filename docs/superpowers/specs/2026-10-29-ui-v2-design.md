# Relay UI v2: professional redesign (design)

Phase A of the upgrade inspired by NectarLink (github.com/thtbee/nectarlink). NectarLink is inspiration only: no copied UI or assets, and no macOS.

## Goal

Move Relay from a basic utility look to a professional, consistent product on both platforms:

- On the PC, a real main window next to the tray.
- On the phone, a tabbed app.
- One shared design system.
- A basic Timeline of what moved between the devices.

Behaviour of existing features does not change.

## Decisions (agreed 2026-10-29)

- **Order:**
  - Phase A, this spec: the UI overhaul.
  - Later phases, one spec each: B Timeline search + command palette + "Copy code" for one-time codes; C media and phone controls (now playing, battery, Do Not Disturb, ringer, volume, flashlight); D messages and calls; E phone as PC remote (touchpad/keyboard/button deck, lock/sleep the PC).
- **PC drawing:** our own kit, moved from GDI to Direct2D + DirectWrite. No new crates; `deny.toml` stays as is.
- **PC shape:** a main window plus the tray. The tray icon, flyout and menu stay for quick actions.
- **Theme:** one brand theme in light and dark, following the system setting. Cobalt `#3651C5` primary and amber for codes, as today.
- **Android:** bottom navigation with four tabs (Home, Timeline, Remote, Settings) plus a home-screen widget.
- **Branch:** `feature/ui-v2`, cut from `feature/clipboard-images`. The v0.1.0 release line (`phase3`) is untouched.

## 1. Design system

- **Source file:** `design/tokens.toml` is the single source for:
  - colours: light and dark sets of surface, surface-variant, outline, text, text-muted, primary, on-primary, accent (amber), success, warning, danger
  - spacing: 4, 8, 12, 16, 24, 32
  - radii: 4, 8, 12, 20
  - type scale: caption 12, body 14, subtitle 16, title 20, display 28 (sizes in px on the PC, sp on Android), with weights
  - motion: fast 120 ms, normal 200 ms, emphasised 300 ms, plus the standard easing curve
- **Generated code:** a generator in `tools/` (a small Rust binary, run by hand) writes `crates/pb-tray/src/tokens.rs` and `android/app/src/main/java/dev/phonebridge/app/ui/Tokens.kt`. Both outputs are checked in.
- **Drift check:** a Rust test reads the TOML and fails if either generated file differs from what the generator would write.
- **Fonts:** native on each platform. Segoe UI Variable plus Segoe Fluent Icons on Windows (both ship with Windows 11); the system font on Android. No bundled font files.
- **Android icons:** Android has no system icon font, so icons are Compose `ImageVector`s, taken from `androidx.compose.material:material-icons-extended`. R8 strips unused icons from the release build. Any icon that set lacks is added as a vector drawable in `res/drawable/`.

## Naming

- **User-visible text** says "Relay" everywhere: the tray tooltip, window titles, the menu, toasts, Android notifications, the widget label and the app label.
- **Internal identifiers stay as they are, for backward compatibility:**
  - the crate and binary names (`pb-tray`, `pb-*`)
  - the Android package `dev.phonebridge.app`
  - the tray data directory `%LOCALAPPDATA%\PhoneBridge\tray`
  - the IPC pipe `\\.\pipe\PhoneBridgeTray-<user>`
  - the window class names
  - the toast app identity
- **Check:** a test lists the user-visible strings in `pb-tray` and fails if any contains "Phone Bridge". `lintRelease` plus a JUnit test cover the Android strings the same way.

## 2. PC rendering kit

- **New module `d2d.rs`:** one `ID2D1Factory1` and one `IDWriteFactory` per process. Each window gets an `ID2D1DeviceContext` drawing into a DXGI flip-model swap chain. The D3D11 device creation already in `screen_render.rs` is reused.
  - `D2DERR_RECREATE_TARGET` (and a lost DXGI device) drops and rebuilds that window's device-dependent resources on the next paint.
- **Swap chain and Mica:** `CreateSwapChainForHwnd` only allows an opaque flip-model swap chain, and that covers the Mica backdrop. So windows that show Mica (the main window and the flyout) work like this:
  - The swap chain is made with `CreateSwapChainForComposition` and `DXGI_ALPHA_MODE_PREMULTIPLIED`.
  - It is shown through DirectComposition: `DCompositionCreateDevice`, an `IDCompositionTarget` from `CreateTargetForHwnd(hwnd, topmost = FALSE)`, and one visual holding the swap chain.
  - The window clears to transparent and paints cards and panes as tinted, partly transparent token colours, so Mica shows through the gaps.
  - `dcomp.dll` is part of Windows, so this needs only extra features on the existing `windows` crate (`Win32_Graphics_DirectComposition`).
- **No Mica:** dialogs and the QR window, and every window when Mica is unavailable (transparency effects off in Windows, or `DwmSetWindowAttribute(DWMWA_SYSTEMBACKDROP_TYPE)` failing), use `CreateSwapChainForHwnd`. They paint opaque surfaces from the tokens. The two paths share all drawing code; only swap chain creation and the background colour differ.
- **Resizing:**
  - `WM_SIZE` calls `ResizeBuffers` and then paints and presents synchronously in the same message, so dragging an edge never shows stale or black borders.
  - The window class has no background brush.
  - `WM_ERASEBKGND` returns 1.
- **`fluent.rs` drawing calls:** text, toggle, button, card, icon and the rest keep their public signatures and draw through Direct2D. Windows move one at a time with no behaviour change, in this order: QR, dialogs, flyout, settings pages. GDI drawing code is deleted when its last caller has moved. The screen and camera video windows keep their D3D11 path.
- **New widgets:**
  - `ScrollView`: wheel and precision-touchpad scrolling with eased offset and an overlay scrollbar.
  - `VirtualList`: lays out only the visible rows (fixed row heights per kind).
  - `SearchBox`: a native `EDIT` child control themed through `WM_CTLCOLOREDIT`, so IME, screen readers, the clipboard and undo keep working. Used in Phase B; built and tested here.
    - Parents that host it have `WS_CLIPCHILDREN`.
    - The DirectComposition target is created with `topmost = FALSE`, so the child control draws above the composed swap chain, and `CreateSwapChainForHwnd` windows clip around it.
    - Direct2D draws the box's rounded border, background and search glyph around the `EDIT` rect. The control itself has no border (`WS_BORDER` off), and its background brush matches the token surface.
    - Verification: type and select text in the box while an animation runs, and check for no flicker or overdraw.
  - `NavRail`, `Card`, `Badge`, `IconButton`, `EmptyState`, `Skeleton`, `InfoBar` (info / warning / error).
- **Layout:** pure functions `(rect, dpi, model) -> Vec<Item>`, tested without a window, as `settings_rows.rs` does today.
- **Animation:** `ease.rs` is extended. A window runs a frame timer only while an animation is in progress, so an idle window uses no CPU.
- **Accessibility:** a visible keyboard focus ring and Tab / Shift+Tab order on every window. Each window has a UIA name. The focused control's name is exposed through the existing accessible-name path.

## 3. PC main window (`main_window.rs`)

- **Frame:** Mica backdrop (DWM), a custom title area with the standard caption buttons, a left `NavRail` (Home, Timeline, Devices, Settings) and a content pane. Window size and position are remembered in `settings.txt`.
- **Custom title bar:**
  - `WM_NCCALCSIZE` extends the client area into the title area.
  - `WM_NCHITTEST` comes from a pure, tested function that returns:
    - `HTCAPTION` for the drag area
    - `HTMINBUTTON`, `HTMAXBUTTON` and `HTCLOSE` for the three caption buttons; returning `HTMAXBUTTON` keeps the Windows 11 Snap Layouts flyout on hover
    - the resize edges (`HTLEFT` … `HTBOTTOMRIGHT`)
    - `HTCLIENT` elsewhere
  - The caption buttons draw their own hover and pressed states.
  - Clicks on them arrive as `WM_NCLBUTTONDOWN` / `WM_NCLBUTTONUP` and are handled there.
  - Maximised windows keep the caption inside the work area. Double-click on the caption maximises (handled by Windows through `HTCAPTION`).
- **Opening it:**
  - Tray left-click still opens the flyout.
  - The flyout gets an "Open Relay" button, and the right-click menu gets an "Open Relay" item.
  - IPC `--open` opens the main window on Home; `--settings` opens it on Settings.
  - A second launch focuses the existing window.
- **Home:**
  - Phone hero card: device name, Connected / Last seen, connection path (Wi-Fi or USB), and the "Reinstalled or reset" warning (`core::is_changed`). With nothing paired, an empty state with a Pair button.
  - Quick actions: Send file, Send clipboard, Phone screen, Camera, Control phone. Each calls the same command the flyout tile uses (`flyout_tiles.rs`).
  - Live sessions strip: screen, camera and control when running, each with Stop.
  - Recent notifications: the last 5 from the state `notify.rs` keeps.
  - Recent activity: the last 5 Timeline items, with "See all" opening Timeline.
- **Timeline (basic):** items grouped by day (Today, Yesterday, date), each showing:
  - kind icon, direction arrow, name or summary, size, peer, time
  - summaries come from section 4's metadata, for example "Text, 142 characters" or "Picture, 1080 × 2412, 1.2 MB"
  - for files: "Open" and "Show in folder"
  - **Missing files:** if the saved path no longer exists, the row shows "File moved or deleted" and those buttons are disabled. This is checked when the row is drawn, and again when a button is clicked, in case the file went away in between.
  - an empty state when history is off or empty
  - Search arrives in Phase B.
- **Devices:** paired devices with name, fingerprint or the "Reinstalled or reset" note (`settings_rows::device_note`), Remove, and "Pair a device" (opens the existing QR flow).
- **Settings:** the existing pages from `settings_groups.rs` / `settings_rows.rs`, drawn inside the content pane with the same keys and behaviour. The standalone settings window is removed; everything that opened it now opens the main window on Settings.
- **Flyout:** redrawn with the new kit. Same tiles, plus a header showing the phone's name and status, and the "Open Relay" button.

## 4. Timeline store

- **Content:** metadata only. Clipboard text, image bytes, file contents and notification bodies are never stored. Each entry records:
  - kind: file, clipboard-text, clipboard-image or notification
  - direction: to phone or to PC
  - peer name and timestamp
  - for files: name, size and saved path
  - for clipboard text: the character count
  - for clipboard pictures: width, height and byte size
  - for notifications: the app name only (no title)
- **Limits:** at most 1,000 entries and 30 days, whichever is smaller. Pruned on write and on load.
- **Settings:** "Keep history" (default on). Turning it off stops recording and deletes the stored history. "Clear history" deletes it.
- **PC:** `timeline.rs`.
  - Pure `encode` / `parse` / `prune` functions. The file is the sealed blob `timeline.sealed` in the tray dir, sealed with the DPAPI helper that `pb-identity` uses for `identity.sealed`.
  - It is rewritten at most once per second (debounced) and on exit.
  - **Atomic writes:** each rewrite goes to `timeline.sealed.tmp`, is flushed (`FlushFileBuffers`), and then replaces the old file with `MoveFileExW(MOVEFILE_REPLACE_EXISTING | MOVEFILE_WRITE_THROUGH)`. A crash or power loss leaves either the old file or the new one, never a partial one.
  - A leftover `.tmp` file found at load is deleted.
  - Only a file that fails to unseal or parse is treated as empty and replaced, and that is logged. A missing file is simply empty.
- **Phone:** `Timeline.kt` replaces the in-memory `Bridge.addRecent` list.
  - A JSON file in `filesDir` (app-private), the same caps, a pure `prune` tested in JUnit, and exposed as a `StateFlow`.
  - Writes go through `androidx.core.util.AtomicFile` (`startWrite` / `finishWrite`, with `failWrite` on error), so a crash mid-write keeps the previous file.
  - Same summary fields and the same missing-file check as on the PC: a deleted file shows "File moved or deleted" and is not opened.
  - Existing callers of `addRecent` write to it.
- **Sync:** none. Each device keeps its own history.

## 5. Android app

- **Navigation:** `androidx.navigation:navigation-compose`. A `NavigationBar` with Home, Timeline, Remote and Settings. System Back follows the standard top-level pattern. Tab state is saved across rotation and process death (`rememberSaveable`).
- **Home:**
  - PC hero card: PC name, Connected / Last seen, and an animated link indicator (the existing `LinkIndicator`, restyled).
  - One "Needs attention" card that lists, in priority order, whichever apply:
    - notification access missing
    - photos permission missing while screenshots are on
    - Control is off while a control request is waiting
    - the PC no longer recognises this phone
  - It replaces today's separate warning cards. The list comes from a pure function tested in JUnit.
  - Quick actions, a 2×3 grid: Send file, Send clipboard, Screen, Camera, Touchpad, Pair.
  - Live session cards (screen, camera, control) with Stop.
- **Timeline:** the store above, grouped by day; tapping a file opens it with the system viewer.
- **Remote:** the `TouchpadActivity` content becomes a composable shown in this tab. `TouchpadActivity` remains as a thin host so existing shortcuts and tiles still work. Phase E's button deck lands here.
  - The touchpad surface uses `Modifier.systemGestureExclusion()` over its whole bounds, so swipes that start near a screen edge move the PC cursor instead of triggering Android's Back gesture. Android limits exclusion to 200 dp of height per edge, so the system may still claim the rest. The pad keeps its edge areas inside the safe insets.
- **Settings:** the existing `SettingsGroups.kt` model with restyled grouped list sections.
- **Look:** a custom Material 3 type scale and shapes from the tokens, edge-to-edge with correct insets, haptic feedback on primary actions, and `AnimatedContent` / `animateContentSize` for state changes.
- **Widget:** a Glance (`androidx.glance:glance-appwidget`) 2×1 widget. It shows the connection state and has two buttons:
  - "Send clipboard" starts `SendClipboardActivity`. Android 10 and later only allow clipboard reads by the app with input focus. So the activity keeps reading the clipboard in `onWindowFocusChanged(true)` (as `SendClip.kt` does today), never in `onCreate`, and the widget path must not bypass that.
  - "Send file" opens the system picker into the existing share flow.
  - The state updates when `Bridge` connection state changes.
- **Code layout:** `MainActivity.kt` becomes a thin host for the `NavHost`. Screens move to `ui/home/`, `ui/timeline/`, `ui/remote/`, `ui/settings/` and `ui/components/`. The adb debug hooks in `MainActivity.handleIntent` stay as they are.

## 6. Out of scope for Phase A

Extra themes or an accent picker, the command palette and search, battery or media data, messages and calls, the button deck, and Linux.

## Error handling

- **Direct2D:** device loss rebuilds resources. If the Direct2D factory cannot be created at all, the tray logs it and shows a dialog saying the window cannot be drawn. The tray icon, toasts and transfers keep working.
- **Timeline I/O:** failures never block a transfer. They are logged and history recording pauses until the next successful write.
- **Widget:** shows "Relay is off" when the service is not running. Taps start the app.

## Testing and verification

- **TDD:** each pure piece gets a failing test first:
  - token drift
  - layout functions: nav rail, home cards, timeline day grouping, virtual-list visible range, scroll easing
  - timeline encode/parse/prune and caps
  - the "Needs attention" list
  - the tab selection state
- **Gates:** `cargo fmt --check`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test --workspace`, `cargo deny check`, `./gradlew :app:testDebugUnitTest lintRelease`, and all four CI jobs green.
- **Real PC** (window-only captures):
  - the main window in light and dark at 100, 150 and 200 % scaling
  - all four pages, the flyout, resizing, keyboard navigation, `--open` / `--settings` routing
  - idle CPU near zero
  - working set under 40 MB with the main window open
  - first paint under 200 ms
- **Real phone:**
  - all tabs, Back, rotation, dark and light
  - Timeline entries after a file and clipboard transfer in each direction
  - the widget (added by the user) and its buttons
- **Regression on real devices:** pairing, files both ways, clipboard text and pictures, notifications, screen and control (including the control auto-off), camera.
- Results go in `docs/DECISIONS.md` as Phase 8. Nothing merges into `phase3` or `main`, and nothing is released, without the user's approval.
